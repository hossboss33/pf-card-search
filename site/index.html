Recent seasons

This index covers 2017-18 through 2022-23 and you can search every card in it right now, with no account and no sign-in.

Why there is no sign-in on this page

Seasons from 2023-24 onward exist only on openCaselist, which requires a Tabroom account to read anything. A sign-in form here would not work, so there isn't one.

The reason is openCaselist's session cookie, and it is worth being exact about because it is not something this site can work around:

  • The cookie is set SameSite=Lax, so browsers never attach it to requests coming from another site. A sign-in would appear to succeed and then every following request would fail as unauthorised.
  • It is scoped to the opencaselist.com domain, so a page served from github.io cannot hold it.
  • Without "remember me" it is a session cookie that dies with the tab — which is why a session that seems to work expires almost immediately.
  • Cookie is a forbidden header name, so a page cannot attach the session itself.

Their search endpoint is also capped at four searches a minute, so even with a working session it could not back a search box. A form that takes your Tabroom password and cannot use it would be worse than none.

How to add the recent seasons

Run the tool on your own machine. There, the sync talks to openCaselist from Python rather than from a browser, so none of the cookie rules above apply and your password never leaves your computer.

git clone https://github.com/hossboss33/pf-card-search
cd pf-card-search
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m carddb serve

Then sign in once and sync. openCaselist issues its session token for two weeks, so this is a fortnightly chore, not a per-search one:

.venv/bin/python -m carddb signin

That opens the sign-in page. Sign in, then press Sync all seasons — one job covers every Public Forum season your login can see, so there is nothing to pick. From the terminal the same thing is:

.venv/bin/python -m carddb login
.venv/bin/python -m carddb sync

Omitting a season name is what makes it walk them all.

carddb login asks for your Tabroom email and password, sends them straight to openCaselist, and stores only the session token it gets back — owner-readable, outside the repo. Your password is never written to disk, never echoed, and never enters your shell history. carddb logout removes the token. There is also a browser version of the same thing at http://127.0.0.1:8321/connect once the server is running.

Those rounds are parsed in full — highlighting, underlining and all — which the browser route could never have given you.

Once synced, rebuilding the published index with scripts/build_site.py puts those seasons on this page for everyone, still with no sign-in.

About this index

What it is

A search index over Public Forum evidence that teams disclosed publicly on openCaselist. Cards are grouped so that one row is one canonical card: the same excerpt disclosed by twenty teams is one result, with the read counts shown next to it.

There is no server. Your browser downloads only the parts of a prebuilt SQLite file that your query actually touches, using HTTP range requests, so searching does not require pulling the whole corpus.

Index contents

Rights in the card text

The body of every card is a quotation from a third-party publication. That text is not ours and is not covered by this project's license; it belongs to the publishers and authors named in each cite. Tags, cites and markup are the work of the debaters who cut and disclosed the cards. Everything here is reproduced for research and study of the public disclosure record, in the form the debaters themselves published it. Cites are never restamped: each card keeps the attribution its original cutter gave it.

If you are a rights holder and want a passage removed, open an issue on the repository and it will be taken out of the next build.
